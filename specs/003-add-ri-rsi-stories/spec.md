# Feature Specification: RI 持续优化与 RSI 经验进化展示

**Feature Branch**: `main`（沿用当前工作分支；逻辑特性 `003-add-ri-rsi-stories`）

**Created**: 2026-10-19

**Status**: Planned — multi-view navigation; PPA evidence deferred per user clarification

**Input**: User description: “为投资人演示补两个 part：RI（recurrent improvement），通过 PPA 优化及趋势图讲持续改进；RSI 从 Agent 已有记忆能力出发，展示记忆不断优化；参考 autoresearch 的实验进展图。分析如何改进现有网页，保持简洁。”

本功能把两个故事分别讲清楚：**RI 改进当前设计，RSI 方向的经验闭环改进后续决策**。展示以真实测量、版本和记忆使用证据为依据；“存在记忆”与“已经证明记忆带来收益”使用不同状态。

## 本次交付范围（2026-10-19 用户补充）

用户明确：“PPA 数据后面才会上线，目前还没有的”。据此分阶段交付：

- **本次**：组织“设计工作台 / 持续优化 / 经验闭环”三个独立入口的页面，共享案例选择与对话上下文；设计工作台保留架构、代码、验证三个内容标签。优化页显示“PPA 数据待接入”，预留后续证据接口，不实现测量流水线、候选搜索或实测趋势图，不安装 PPA 工具链。经验页展示经审核的真实材料，并补齐当前执行后端的记忆读取、使用记录与修订证据。
- **后续 PPA 接入**：有真实数据后，再实现实验点、合格最佳阶梯线及对应详情。FR-004～009、SC-002/003 与 US1 的有数据场景作为届时的接入验收条件；它们不阻塞本次无 PPA 数据版本交付。FR-010 的缺测提示现在即适用。
- **证据验收**：FR-023 的 RI 部分延后；经验闭环部分仍需真实运行材料。界面完成、经验闭环完成、RI 数据就绪分别记录，不以空状态宣称优化收益或完整 RI 故事已交付。
- **演示验收**：本次 SC-001 的路径改为“优化待接入说明 → 经验来源与复用 → 对应验证 → 对话提问”；SC-006 的问答覆盖经验依据及“目前是否有 PPA 结果”。原有数据完整演示路径保留为后续目标。

此范围补充优先于下文对完整故事的材料准备要求，避免把未来 PPA 工作列为本次实现前置条件。

**导航补充**：用户随后明确“不一定要保持单页，可以按照你觉得好的规划拓展”。取消必须把所有内容放进同一页面或五个同层标签的约束，采用上述三个页面，保持导航清晰、演示简洁。各页面可直接打开、刷新和前进/后退；跨页面不丢失本案例对话、草稿及可兼容的证据选择。拆分展示页面不意味着增加管理系统或独立后端。

## 演示叙事调整（2026-10-19 用户最新补充）

用户说明目前没有具体落地技术，希望网页先讲清“记忆机制、Agent 的观测、评估与进化”的故事，不需要展开工程实现。本补充调整本次展示口径：

- 自进化页以机制构想为主体：观测 → 评估 → 记忆 → 改进 → 再验证，用可点击流程和明确标注的场景推演解释反馈如何进入下一轮决策。
- RI 讲当前设计的持续改进；RSI 方向讲经验与策略如何辅助后续任务。记忆从设计经验、失败边界、任务策略三个角度说明，不做虚构收益曲线或数字。
- 不以真实两运行和修订素材作为本次概念叙事的展示前置；已有真实工程记录保留在折叠区，原验证与私有隔离规则继续生效。
- 页面须清楚标注演进方向/机制构想，不能把说明性场景说成已经完成的自动进化、模型训练或实测提升。原实证验收仍独立记录为未完成，不由概念页替代。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 看到设计在多轮实验中如何优化 (Priority: P1)

作为演示者，我希望在“持续优化”页面看到同一设计各轮实验的 PPA 变化、保留或放弃原因，以及目前最佳的有效版本，从而用一张图说明 RI 的过程和结果。

**Why this priority**: 将“Agent 能写 RTL”推进为“Agent 能围绕工程目标持续试验”，并允许投资人追溯每次收益的依据。

**Independent Test**: 加载一个具有基线及至少两轮候选测量的真实案例，查看趋势、选择一轮实验，并打开其 RTL、验证报告和测量依据；不依赖 RSI 记忆对照才能理解 RI。

**Acceptance Scenarios**:

1. **Given** 同一案例有基线和可比较的实测结果，**When** 打开“优化”，**Then** 显示优化目标、测量范围、基线/当前最佳值、单位、约束，以及按实验轮次排列的候选点和历史最佳阶梯线。
2. **Given** 一轮候选通过功能验证并满足约束，**When** 主要目标达到事先约定的有效改善标准，**Then** 该轮可标为保留并更新最佳结果；改善不足、恶化或违反约束的候选保持原始值和实际处置原因。
3. **Given** 候选功能验证失败或测量失败，**When** 展示该轮，**Then** 显示对应失败状态，不将其纳入合格最佳值；没有测量数值时不用零值代替。
4. **Given** 用户选择某个实验点，**When** 查看详情，**Then** 能看到这一轮的改动摘要、采用的起始版本、功能验证结果、测量条件及保留/放弃原因，并打开同一版本的代码、报告和已有波形。
5. **Given** 没有可信功耗数据，或只测量了一个子模块，**When** 查看优化结果，**Then** 功耗标为未测量，范围明确为该子模块，不扩大成整个 E203 或芯片的 PPA 结论。
6. **Given** 当前没有 PPA 记录，**When** 打开“优化”，**Then** 显示“待采集测量数据”和缺少的证据；可展示不含虚构成绩的流程示意，但不能显示实测改善曲线或成功百分比。

### User Story 2 - 看到经验如何形成、复用和修订 (Priority: P1)

作为演示者，我希望在“经验闭环”页面看到一次失败或修复如何沉淀为经验，之后的任务如何使用该经验，以及新证据如何修订或淘汰经验，从而说明 RSI 方向的经验驱动改进。

**Why this priority**: 将“有聊天历史”与“工程经验可被后续任务利用”区别开，让自我改进故事有可检查的因果链。

**Independent Test**: 打开一条真实经验，追溯来源任务、实际使用它的后续任务和后续验证，再查看一次有来源依据的经验修订；即使没有 PPA 数据，也能独立说明这条经验闭环。

**Acceptance Scenarios**:

1. **Given** 已归档修复结果或失败方向，**When** 查看经验条目，**Then** 显示问题类型、可复用的经验、适用条件、应避免的做法、来源和实际验证层级，而不将文件数量当作能力提升分数。
2. **Given** 某条经验只有存档证据，**When** 展示其状态，**Then** 标为已沉淀；只有真实检索、提供给执行者或采用的记录，才分别显示对应阶段，不把检索到直接写成采用成功。
3. **Given** 后续任务实际采用了一条经验，**When** 查看复用链，**Then** 能定位到当时使用的经验版本、使用目标、采用依据和后续验证结果；经验来源与使用任务必须可以区分。
4. **Given** 新任务证明旧经验存在适用限制或错误，**When** 查看修订，**Then** 保留旧版本，并展示新版本调整了什么、为什么调整及依据；尚未再次使用的新版本保持待验证状态。
5. **Given** 有同条件的启用/不启用记忆对照，**When** 显示收益，**Then** 展示两次实际结果、投入及条件差异；只有一个对照样本时注明其范围，不推广为普遍收益。
6. **Given** 缺少实际复用、修订或对照证据，**When** 查看经验展示，**Then** 已有条目仍可浏览，缺少的环节明确显示未记录或待验证，不生成学习速度、成功率提升等数字。

### User Story 3 - 在同一站点连贯讲述设计与两个改进故事 (Priority: P1)

作为演示者，我希望通过清晰导航切换设计工作台、持续优化和经验闭环，持续通过对话提问，并让投资人随时打开依据。

**Why this priority**: 保持首版简单，并将两个新故事与已有规格、架构、RTL 和仿真波形连在一起。

**Independent Test**: 在已准备材料的情况下，用 90 秒完成“查看优化趋势 → 选择一轮 → 查看验证 → 查看关联经验 → 提问为什么”的跨页面演示；切换页面或工作台内部标签不丢失对话或任务选择。本次无 PPA 版本按范围补充的路径验收。

**Acceptance Scenarios**:

1. **Given** 打开站点，**When** 使用主导航，**Then** 可以进入设计工作台、持续优化、经验闭环；工作台保留架构、代码、验证，对话在三个页面均可使用。
2. **Given** 当前选中了某轮实验或某条经验，**When** 询问“这一轮为什么保留”“这条经验如何影响后续任务”，**Then** 回答基于当前选中记录，提供已有证据引用，证据不足则说明缺失。
3. **Given** 正在浏览历史优化或经验案例，**When** 播放记录或询问结果，**Then** 页面和回复均保留历史标识，不把记录加载或动画播放称为刚完成了优化或学习。
4. **Given** 实时执行不可用，**When** 浏览新页面或工作台内部标签，**Then** 仍可查看真实归档材料；问答按实际后台连接状态工作，浏览不会自动启动优化、生成、仿真或付费模型请求，不新增无条件可点击的重型操作入口。
5. **Given** 切换 E203、AES 或 SDC，**When** 新案例没有对应证据，**Then** 显示该案例的空状态，不沿用前一个案例的收益、记忆或结论。
6. **Given** 直接打开一个有效的经验或验证链接，**When** 刷新或使用浏览器前进/后退，**Then** 恢复对应页面与经校验的案例/证据选择；公共链接不携带私有会话标识或聊天内容。

### Edge Cases

- 优化面积但时序不满足约束时，候选不进入合格最佳线；其他目标与约束组合遵循相同原则。
- 功能修复过程中不匹配数减少，只能作为功能进展，不能换算为面积、功耗或时序收益。
- 测量对象、工艺/器件条件、时钟约束、活动负载（如适用）、评估阶段或方法不同的记录，不放在同一可比较收益序列中。
- 无效基线、基线为零、单位不同、缺测或数值异常时，不计算误导性的改善比例。
- 失败尝试和负向经验保留；缺少数值的尝试展示状态，不把它放在最优值零点。
- “已通过局部验证”不能自动升级为系统复验通过或形式证明；有限测试下的通过保留其覆盖范围。
- 多条重复记录或经验修订不能人为抬高经验数量、独立成功次数或复用收益。
- 经验源文件被修改、引用材料缺失、当时使用的版本无法恢复时，对应链路标为证据不完整。
- 某个执行后端有记忆逻辑、另一个没有时，展示实际来源和后端能力，不能把前者的历史记录当作后者正在复用的证明。
- 不同访客的私有对话和任务记录不能自动进入公共经验库；仅允许当前会话授权材料或经确认的公共演示材料。
- 记忆对照的起始设计、模型、评估、预算或其他条件不同，须展示差异并标为不可直接归因；没有收益或出现退化时照实展示。
- 刷新、断连、跨页面/标签或跨历史/实时模式切换不能混用实验、RTL、验证、波形及经验版本；无权访问或过期链接不能回退到另一条看似成功的记录。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供设计工作台、持续优化、经验闭环三个清晰的页面入口，保留跨页面可用的对话、四案例、工作台原架构/代码/验证和波形查看。页面可直接打开、刷新及使用浏览器前进/后退；不将单页布局作为硬性约束。
- **FR-002**: 优化和经验页面必须分别用一句自然语言说明“RI：在验证约束内改进设计”和“RSI 方向：积累、复用并验证工程经验”；经验积累、已发生复用和已验证收益须呈现为不同状态。
- **FR-003**: 所有新展示必须明确区分真实归档、实时执行和流程示意。流程示意不能包含看似实测的成绩、收益百分比或虚构成功事件。
- **FR-004**: 每组优化记录必须声明案例、测量对象及范围、主要目标及改善方向、约束、基线版本、单位和评估条件。基线必须有对应的功能验证通过记录，否则保持功能修复或基线待验证状态。首版优先面积与时序，未测功耗明确标为未测量。
- **FR-005**: 面积估计、单元数量代理、时序估计、布局布线结果及其他阶段必须按实际报告标注；单元数量不能冒充物理面积，推算值不能冒充对应阶段实测值。
- **FR-006**: 优化图必须按实验轮次呈现有数值的候选点及合格历史最佳阶梯线；同时保留失败、放弃及未完成尝试的状态，不隐藏造成退化的记录。
- **FR-007**: 候选只有通过对应版本的功能验证、满足事先声明的约束并达到预定有效改善标准，才能更新合格最佳结果。改善落在已知测量不确定性内时不得宣传为确定收益。
- **FR-008**: 改善率必须基于同条件、同单位基线计算，明示升高或降低哪项指标才是改善；不能把不同比较口径合并为未经定义的 PPA 综合分。
- **FR-009**: 选择任意实验点必须能查看其起始与候选版本、改动摘要、测量依据、验证结果及处置原因，并跳转到对应版本的代码、报告和已有真实波形。
- **FR-010**: 缺少可信测量、可比较基线或功能验证时，系统必须展示具体缺口，不生成优化成功结论；没有改善时允许显示持平或退化。
- **FR-011**: 经验条目必须包含来源任务/尝试、经验内容、适用条件、正向做法或失败方向，以及实际验证层级。缺少的字段保持未记录，不按文件名称或模型叙述推断为已验证事实。
- **FR-012**: 经验状态必须按证据区分已沉淀、已检索、已提供给执行者、已采用和采用后的验证结果；不能从某阶段自动推断下一阶段已发生。
- **FR-013**: 经验必须支持有依据的修订或淘汰展示，保留各次内容、来源、变更原因和状态；历史任务绑定其当时实际使用的经验版本，不随条目更新而改变。
- **FR-014**: 一条复用链必须连接经验来源、当时的经验版本、实际使用的后续任务及其验证结果；仅打开经验卡片或检索命中不得计为工程采用。
- **FR-015**: 若宣称记忆带来可量化收益，必须提供同起始设计、规格、模型设置、评估条件与预算的启用/不启用对照，并披露其余差异；只展示实际记录的尝试次数、耗时或资源投入，不补算未记录的成本。
- **FR-016**: 单次对照必须标明样本范围，不当成统计显著性或跨任务普遍提升证明；没有对照时显示“收益待验证”。经验文件数量和规则型置信度不能当作成功率或能力分数。
- **FR-017**: 新证据与旧经验冲突时，系统必须优先展示当前验证事实，允许经验被修订或淘汰；经验不能改变规格、参考设计和评价规则以制造改善。
- **FR-018**: RSI 展示必须表述为工程经验驱动的后续过程改进；除非另有独立证据，不得宣称模型权重训练、Agent 自主改写自身算法或已证明强意义的递归自我改进。
- **FR-019**: 对话必须理解当前所选优化轮次或经验，并用自然语言解释目标、处置和依据；引用须指向当前可访问材料。缺失复用、收益或实时执行证据时，回答必须保留这些限制。
- **FR-020**: 优化和经验页面必须支持独立于现场重型执行的真实历史浏览；查看、播放、刷新或切换页面/标签不能自动触发新实验、模型问答或资源安装，实时操作继续遵循既有准入条件。
- **FR-021**: 系统必须延续当前会话隔离。公开故事仅使用审核后的演示材料；私有聊天、未授权项目、秘密、参考设计私有源码及内部路径不得因经验展示而公开。
- **FR-022**: 新展示必须继续绑定案例、运行、RTL 版本、验证及波形，并补充优化轮次与经验版本关系；任何缺失或冲突都必须显式标记，而不是借用其他记录补齐。
- **FR-023**: 首个对外 RI 材料必须至少包含一个基线和两个具有真实可比测量的候选版本，并保留实际处置。首个对外经验闭环材料必须至少连接两个真实运行，展示一次实际复用及一次有依据的修订或淘汰；只有存档卡片不能算完整 RSI 故事交付。
- **FR-024**: 功能界面检查与故事证据验收必须分别记录。没有达到 FR-023 时，界面可显示准备中，但不能宣称两个故事已完成；若需要宣传记忆收益，还须满足 FR-015/016。

### Key Entities *(include if feature involves data)*

- **优化活动**：同一案例、同一测量范围和可比较条件下的一组实验；包含目标、约束、有效改善规则、基线及目前合格最佳版本。
- **实验轮次**：一次设计候选及其起始版本、改动、功能验证、测量、处置和对应证据；关联已有代码与波形。
- **测量观察**：一项有单位、方向、测量对象、评估阶段和条件的原始结果；区分实测、估计、代理及未测量。
- **经验条目及修订**：由任务证据形成的经验和它的历史内容、适用条件、验证层级与生命周期状态。
- **经验使用记录**：某一后续运行实际检索、接收或采用的特定经验修订及其结果，能够与来源运行区分。
- **收益对照**：声明可比条件、记忆使用差别、实际结果和投入的成对运行；记录样本范围和不可归因项。
- **故事证据集合**：经审核可展示的案例、实验、验证、波形及经验链，用于投资人演示而不包含其他访客的私有会话。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 材料准备就绪时，演示者能在同一站点 90 秒内完成“优化曲线 → 某轮依据 → 对应验证 → 经验复用链”的跨页面展示，全程可继续在对话框输入。
- **SC-002**: 首个 RI 案例至少展示 3 个真实、同条件的版本测量（基线加两个候选）；所有实验点都能定位对应版本、功能验证、测量及处置依据，追溯完整率 100%。
- **SC-003**: 功能失败、违反约束、测量缺失和条件不可比的候选，在验收样例中进入合格最佳线的数量为 0；展示的改善比例全部可由原始可比数值复算。
- **SC-004**: 首个经验案例至少包含 1 条跨两个真实运行的来源—复用—后续验证链，以及 1 次可追溯修订或淘汰；没有使用证据的条目被标为已采用的数量为 0。
- **SC-005**: 所有标为“已验证收益”的记忆结论都有符合声明条件的成对对照；无对照、不可比或单次样本的范围提示覆盖率 100%，不从记忆数量推导收益。
- **SC-006**: 至少两轮围绕选中实验和经验的真实问答能给出有效依据；切换页面/标签和刷新后选择与对话不串案例，缺失材料时不宣称已有结果。
- **SC-007**: 当前案例已加载时，至少 95% 的站内页面切换与工作台标签切换在 1 秒内显示已归档内容或明确空状态；在 1366×768 桌面视口不新增页面级横向滚动，对话仍可访问。
- **SC-008**: 新增两部分后，四案例的原架构/代码/验证和真实波形流程仍通过验收；仅浏览页面触发的新增重型任务及模型问答数量为 0，独立访客互见私有会话的数量为 0。

## Assumptions

- 首版面向投资人桌面演示，采用设计工作台、持续优化、经验闭环三个页面，共享案例与对话；页面数量可随实际内容扩展，优先清晰和简洁，不增加管理后台、通用实验平台或独立记忆编辑器。
- RI 按用户本次约定指 recurrent improvement，即在目标和验证约束下持续提出、评估和选择设计候选；RSI 采用“经验驱动改进”方向的叙事，并显式保留证据阶段。
- E203 为首选演示案例。若只具备其某个子模块的可靠测量，必须明确标注范围；其他三案例逐步补充真实材料，不复制 E203 数值。
- PPA 首期优先有报告支持的面积与时序，功耗为可缺项；不承诺固定改善比例，也不要求每轮实验都变好。具体测量条件和输入材料在计划阶段落实。
- 目前已有 RTL 长期经验机制和历史条目可以作为素材，但来源、实际采用、收益和当前执行后端的支持情况须分别核对；聊天记录和一般上下文记忆不直接作为该故事的工程改进证据。
- 历史材料先在适当环境准备、验证并审核后展示；首版不要求在当前小内存公网服务器上现场完成 PPA 实验或无限自主优化，也不解除既有执行门禁。
- 参考 autoresearch 的实验点、保留/放弃状态和历史最佳线表达方式，采用本项目自己的验证规则和真实数据，不复制它的训练成绩或隐去退化实验。
- 当前入口保持 `agent.deepvalleychip.cn`，`design.deepvalleychip.cn` 保持独立原静态页面；本特性不修改已确定的域名职责。
- 本轮产出规格与设计分析，后续通过计划和实现阶段补齐证据采集及页面；不是宣告新增能力已上线。
