# Feature Specification: RTL Agent 投资人演示工作台

**Feature Branch**: `main`（本次仅创建功能规格，未新建分支）

**Created**: 2026-10-15

**Status**: Draft

**Input**: User description: "为现有 RTL Agent 创建面向投资人的单页网页演示工作台。包含持续可交互的对话框，支持围绕当前任务提问和发起操作；展示规格理解、多模块架构规划、RTL 生成、仿真与自动修复过程；支持查看真实 DUT 与参考设计波形、定位差异及修复前后对比。以 E203 为首个案例，明确区分历史运行回放和实时执行，并将验证结果、RTL 版本与波形绑定。保持第一版功能简洁。" 补充要求："不要把网页设计的太复杂。"

2026-10-15 部署补充：沿用 Deep Valley Chip 现有服务器与 design 域名；用户确认实时后端运行在现有大内存服务器，私网信息稍后补充。

2026-10-16 用户扩展：加入 `aes_cipher_system_hard`、`aes_inv_cipher_top_system`、`sdc_controller_system`，与 E203 共用同一个页面，通过顶部下拉框选择，持续对话绑定当前任务。保留三个标签和简洁布局。E203 修复前失败必须明确标注为历史版本，最终独立验证显示真实 PASS。新增案例只展示已有记录；缺少修复前波形或采样统计时说明缺失。下文原始 E203 验收仍适用，其余案例按相同的版本/报告/波形绑定规则展示。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在一个页面讲清技术能力 (Priority: P1)

作为演示者，我希望打开预置的 E203 案例后，在一个页面展示规格摘要、模块架构、生成代码和验证结果，让投资人理解 Agent 从硬件需求到仿真验证的完整过程。

**Why this priority**: 先用已有真实案例提供完整、易于理解的展示，控制首版界面和操作数量。

**Independent Test**: 只加载一个已保存案例，即可演示规格摘要、模块关系、生成代码和验证报告，无需现场启动生成任务。

**Acceptance Scenarios**:

1. **Given** 演示者打开工作台，**When** E203 案例加载完成，**Then** 同一页面显示案例名称、简短规格摘要、当前模式、阶段进度和持续可见的对话框。
2. **Given** 案例包含真实规划和代码，**When** 演示者在“架构”“代码”“验证”三个标签间切换，**Then** 分别看到模块层次与职责、所选版本的只读 RTL、该次验证报告；对话内容保留。
3. **Given** 正在历史回放，**When** 演示者播放、暂停或继续回放，**Then** 页面按已有记录展示规格理解、架构规划、代码生成、仿真和修复事件；尚未回放到的结果不冒充已完成事件。
4. **Given** 历史记录未保存某阶段的细节，**When** 回放到该阶段，**Then** 标明细节未记录，不生成虚构过程、耗时或执行百分比。

---

### User Story 2 - 通过对话提问并发起操作 (Priority: P1)

作为演示者，我希望自由输入关于当前设计的问题，并通过对话发起验证、生成或修复，让投资人看到可交互的 Agent。

**Why this priority**: 持续可交互的对话框是硬性要求，必须连接当前任务和真实结果。

**Independent Test**: 使用已有案例连续询问架构与验证结果，再发起一次实际验证，检查回答依据、操作状态和页面结果是否一致。

**Acceptance Scenarios**:

1. **Given** 已加载 E203 案例，**When** 用户连续输入“这个设计负责什么”“为什么单独划分乘除法模块”等问题，**Then** Agent 结合当前规格和规划回答，保留上下文，并为涉及的模块或产物提供查看入口。
2. **Given** 用户要求“重新验证当前设计”，**When** 请求被接受，**Then** 对话显示本次操作的运行状态，右侧显示同一次操作的验证结果；只有实际调用验证后才报告执行完成。
3. **Given** 用户输入无法确定目标的执行请求，**When** Agent 尚不能确定操作，**Then** 在对话中简短询问目标，保持已有结果，等待明确回复后执行。
4. **Given** 用户请求首版范围外的操作，或问到现有材料无法支持的事实，**When** Agent 回复，**Then** 说明能力或证据不足；推测和建议与已验证事实明确区分。
5. **Given** 正在运行一个操作，**When** 用户继续询问进度或设计问题，**Then** 对话仍可接收并回答；重复发送同一执行请求不会重复启动任务。

---

### User Story 3 - 查看真实波形并对比修复前后 (Priority: P1)

作为演示者，我希望直接在验证页查看生成设计（DUT）与参考设计（Reference）的真实仿真波形，定位已记录差异，并展示修复后的结果。

**Why this priority**: 投资人能够从仿真报告追溯到具体信号和时间，判断结果是否有可信证据。

**Independent Test**: 加载一组已有的失败与通过记录，定位一次真实差异，再切换到修复后的同一时间窗口，核对波形与各自报告。

**Acceptance Scenarios**:

1. **Given** 所选验证有真实波形，**When** 用户打开“验证”标签，**Then** 可见时钟、复位、关键握手信号和写回数据的 DUT/Reference 对比，能缩放、平移并用游标读取时间和数值。
2. **Given** 所选失败记录提供差异信号与时间，**When** 用户点击“定位差异”，**Then** 波形定位到对应时间窗口，标明信号及差异；比较规则与该次测试平台一致。
3. **Given** 同一案例存在可比较的修复前后记录，**When** 用户切换“修复前”“修复后”，**Then** 保持同一信号组与可用的相同时间窗口，分别显示其 RTL 版本、验证状态和对应波形。
4. **Given** 最终报告为通过，**When** 用户查看结论，**Then** 页面展示报告中已记录的采样点总数与不匹配采样点数；报告未记录时明确说明，不影响受信验证器的明确结论，不填造统计；说明结论适用于该次测试，局部波形相似不能单独产生通过结论。
5. **Given** 波形缺失、版本对应关系无法确认或信号不存在，**When** 用户查看或切换，**Then** 显示具体缺失项，不借用其他版本波形，也不把未知值自动当成一致。

---

### User Story 4 - 现场执行生成、验证和自动修复 (Priority: P2)

作为演示者，我希望基于预置 E203 规格调用现有 Agent 执行流程，在生成设计后运行系统验证，并在失败时查看自动修复与复验过程。

**Why this priority**: 现场操作补充历史案例的说服力；沿用已有执行能力，避免扩展成完整开发平台。

**Independent Test**: 在准备好的运行环境中，通过对话发起一次 E203 生成与验证，并针对失败版本发起修复；验证操作记录、代码变更、接受或回滚结果和最终报告相互对应。

**Acceptance Scenarios**:

1. **Given** 实时执行依赖可用，**When** 用户明确要求从预置规格生成并验证，**Then** 创建新的运行记录，调用现有流程，展示实际阶段与模块完成状态，并保留历史演示案例。
2. **Given** 有已完成的 RTL 版本，**When** 用户要求重新验证，**Then** 创建新的验证记录并运行实际验证，不覆盖旧记录，也不自动触发重新生成。
3. **Given** 当前实时版本验证失败，**When** 用户要求尝试修复，**Then** 展示已有 Debug 流程产生的定位证据、代码差异、候选验证及接受或回滚结果；遵循当前运行配置的次数与时间限制。
4. **Given** 候选修改通过局部检查，**When** 系统尚未完成最终系统复验，**Then** 页面保持最终验证未完成状态，直到独立验证结果可用后再更新结论。
5. **Given** 运行失败、超时或依赖不可用，**When** 操作结束，**Then** 显示失败原因和最后完成阶段，保留历史证据；只有明确选择历史回放后才切换模式。
6. **Given** 工作台部署至 design 域名，**When** 演示者通过受保护的入口访问并发起验证，**Then** 请求到达私网计算后端并返回对应结果；主站和 www 保持原有内容，未授权访问不能发起操作。

---

### Edge Cases

- 没有案例产物时，展示“案例数据未准备”的空状态和缺失项，不显示成功指标或演示波形。
- 模型服务暂不可用时，对话明确提示当前无法回答或执行；已加载的规格、代码、报告和波形仍可浏览，之后可重新发送请求。
- 一个实时操作进行中时，拒绝启动另一个会生成或修改 RTL、运行验证的操作，并显示当前操作；只读提问和历史浏览仍可使用。
- 浏览器刷新或临时断连后，重新进入同一会话可查看已保存消息和已记录的操作状态；恢复界面本身不创建新操作。状态无法确认时显示“状态待确认”，不标为通过。
- 用户在运行中切换历史记录时，后续实时结果仍归属于原运行，不替换当前选择的历史报告或波形；提供返回实时运行的入口。
- 历史与实时记录使用不同统计口径时，分别标明“不匹配采样点数”“内部差异计数”“候选验证次数”；缺少采样点统计时显示未记录，不换算为零。
- 修复前后的仿真时间范围不一致时，说明可比较范围；范围外不补造数据。波形使用记录中的时间单位，并与真实运行耗时分开标注。
- 语法检查失败、系统仿真失败、证据缺失、执行错误和最终通过须呈现不同状态；没有触发修复时显示“未触发”，不虚构修复次数。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供一个面向桌面演示的单页工作台，持续显示对话框；设计内容仅以“架构”“代码”“验证”三个主标签切换，波形位于验证标签内，规格摘要可折叠查看。
- **FR-002**: 系统必须预置 E203、AES 加密、AES 解密和 SDC 控制器四个案例，用一个下拉框切换，展示各自实际规格摘要、规划模块层次与职责、阶段状态和模块完成情况；代码只读，选择模块后可查看其对应 RTL。
- **FR-003**: 系统必须依据已有记录展示从规格理解到修复与验证的历史过程，提供播放、暂停、继续功能；缺失阶段细节显示未记录。
- **FR-004**: 系统必须在页面和每条操作结果中明确标注“历史回放”或“实时执行”；历史操作展示当时已保存的结果，实际发起执行时须明确进入实时运行。
- **FR-005**: 对话必须支持自由文本、多轮上下文和当前任务相关问答；每条消息关联其所属案例、运行以及引用的 RTL 版本或验证记录，切换标签不清空对话。
- **FR-006**: 涉及具体模块、代码、验证结论或波形的回答必须提供对应证据入口；没有证据时说明不足，不能把建议或推测描述为实际执行结果。
- **FR-007**: 对话必须支持发起“按预置规格生成并验证”“重新验证所选 RTL 版本”“分析并修复失败版本”三类操作，并提供简短示例帮助开始使用。目标不明确时先澄清，范围外请求给出范围说明。
- **FR-008**: 每个实时操作必须显示已接受、运行中及最终状态；展示实际阶段和可用结果，在执行环境产生状态更新后同步呈现，不伪造进度百分比。
- **FR-009**: 每个演示会话同一时间最多执行一个实时生成、验证或修复操作；并行请求显示当前操作、拒绝重复启动，已有只读交互保持可用。
- **FR-010**: 实时执行必须使用既有 RTL Agent 和实际验证流程；生成创建新的运行，重新验证创建新的验证记录，修复创建新的候选版本；历史演示数据和已验证版本必须保留。
- **FR-011**: 修复过程必须能查看已产生的失败证据、修改文件与代码差异、每次候选验证以及接受或回滚结果；失败、超时和预算耗尽均如实呈现，不保证每个请求都能修复成功。
- **FR-012**: 系统必须将每次验证的案例、运行、RTL 版本、测试配置标识、原始报告和波形绑定；缺失或不一致时阻止把这些产物组合为已核验的结果。重新验证同一版本也具有独立记录。
- **FR-013**: 最终通过状态必须来自对应 RTL 版本的独立系统验证结果；语法检查通过、Agent 的自然语言判断或局部波形观察均不能代替最终验证。修复结束后须展示最终复验结果。
- **FR-014**: 验证摘要必须分别呈现通过状态、测试采样点数、不匹配采样点数和候选验证次数（含语法检查失败的尝试）；仅显示报告中存在的指标，并提供原始报告查看入口。
- **FR-015**: 波形必须来自所选验证对应的真实仿真数据，首版提供固定的关键输入、时钟复位、握手和 DUT/Reference 写回输出信号组，支持缩放、平移及游标时间与数值读取。
- **FR-016**: 对于已有差异证据，用户必须能一键定位相应信号和时间；差异显示遵循测试平台的采样、有效条件及未知值处理规则，并保留记录的时间单位。
- **FR-017**: 用户必须能切换可比较的修复前后记录，保留相同关键波形信号和可用时间窗口，同时更新版本、报告及结果标签；缺失数据或不可比较范围须明确提示。
- **FR-018**: 系统必须对空数据、模型或验证依赖不可用、运行错误、超时和波形缺失提供可见状态与原因，保留可浏览的已有结果；刷新或断连恢复不自动重复执行操作。
- **FR-019**: 首版操作仅针对四个预置规格及各自演示运行产物；切换案例保留各自会话，不能跨案例执行或混用证据；规格、参考设计和测试平台保持只读，自动修复仅修改当前实时运行的生成 RTL。
- **FR-020**: 界面必须用简短中文说明“DUT＝生成设计”“Reference＝参考设计”和当前测试范围；消息、阶段状态和验证结果同时使用文字标识，不能仅依赖颜色表达。
- **FR-021**: 工作台必须可部署至 `design.deepvalleychip.cn` 的受保护演示入口，实时能力由现有大内存服务器提供并仅通过私网接入；现有主站与 www 的内容和访问方式保持原状，不开放匿名任务执行。

### Key Entities *(include if feature involves data)*

- **演示案例**：预置 E203 规格、简介和关联历史运行的集合；案例具有稳定标识，首版只提供一个。
- **演示会话与消息**：同一次演示中的用户和 Agent 对话、所选记录与执行操作；消息保存角色、顺序、内容、历史或实时来源及证据引用。
- **运行与操作**：一次历史或实时执行的身份、目标、来源模式、实际阶段、状态和错误；操作记录其输入版本与输出产物，单个会话最多有一个活动实时操作。
- **RTL 版本**：运行中的一份可追溯代码快照，包含版本标识、所属运行、父版本及候选、接受或回滚状态；验证引用后的版本内容不随后续修复变化。
- **验证记录**：独立标识、所属运行、受测 RTL 版本、测试配置、验证类别、状态、统计指标及原始报告；一次版本可对应多次验证，缺失指标与零值区分。
- **波形证据与修复尝试**：波形属于具体验证，包含信号、时间单位与范围、差异位置；修复尝试关联输入版本、候选修改、验证记录及接受或回滚决定。修复前后比较通过这些关系选择配对记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在准备好的桌面演示环境中，案例首次打开后 5 秒内可浏览规格摘要、模块架构和对话输入；在 1366×768 及更大视口下，三个主标签与输入框无需整页横向滚动即可操作。
- **SC-002**: 演示者可在 3 分钟内完成一次预置历史回放，展示规格、模块架构、RTL、真实失败、修复及最终验证证据；该时长仅适用于回放，不代表真实生成耗时。
- **SC-003**: 在连续 10 轮案例问答和标签切换中，对话均保留上下文；对设计和验证事实的回答全部可追溯到所选任务的证据，证据不足的回答明确标注。
- **SC-004**: 在已准备运行环境中，三类对话操作各至少成功接入执行一次；用户发送执行请求后 3 秒内看到接收或拒绝状态，运行产生阶段或终态信息后 5 秒内可在页面看到，实际失败也作为有效执行结果如实展示。
- **SC-005**: 对预置的一组失败与通过记录，用户可在两次点击内从验证结果打开并定位差异波形，切换修复前后后，信号、可比较时间窗口、RTL 版本与报告全部对应。
- **SC-006**: 在通过、仿真失败、语法失败、报告缺失和版本不匹配五类验收场景中，仅对应版本的独立系统验证通过能产生最终通过标识；所有展示结果均能识别历史或实时来源。
- **SC-007**: 使用已准备的 E203 最终通过记录时，页面准确呈现该记录中的 222 个采样点与 0 个不匹配采样点；换用其他记录时随原始证据更新，不能固定显示这些数字。
- **SC-008**: 在重复请求、刷新、临时断连、依赖不可用和执行超时五类场景中，不产生重复执行或虚假成功；已有对话和已记录结果可继续查看或在重连后恢复，状态不明时明确提示。
- **SC-009**: 服务器验收时，演示者可从受保护的 design 域名完成一次真实问答和系统复验；未授权请求不能执行操作，计算后端不提供公网直接访问；主站与 www 保持原有内容及访问方式。

## Assumptions

- 首版由一名演示者通过受保护的 design 域名或本地开发环境操作，投资人通过演示屏幕观看并可由演示者代为输入问题；公网入口沿用现有网关，实时后端位于私网大内存服务器。首版使用共享演示访问保护，不提供匿名自助任务、多用户协作、账号注册或多租户能力。
- 界面采用“左侧持续对话、右侧三个内容标签”的简洁布局，不增加独立项目管理页、复杂知识图谱浏览器、在线代码编辑器、自由波形信号管理或额外配置面板。
- 首版使用四个固定预置规格，支持为所选案例新建实时运行；上传任意规格、用户自行新增案例、在线修改规格以及跨案例管理留待后续。
- E203 历史数据已保存仓库规划、生成 RTL、候选验证记录、最终系统验证报告和部分阶段细节；预置演示前需准备一组可关联的失败与修复后通过波形。缺失内容按未记录处理，不要求补造历史。
- 实时生成、问答、仿真和修复依赖现有 Agent 的模型配置、仿真工具及外部测试环境；这些依赖由演示者在演示前准备，网页不承担安装、模型配置管理或验证器重写。
- 历史回放可在实时执行依赖不可用时继续浏览；问答服务不可用时必须明确提示，不能用固定回复冒充实时 Agent 回答。
- “正确”指指定测试配置下独立系统验证通过；首版不宣称形式证明、全部输入覆盖、综合结果、面积、功耗或芯片可制造性。
- 本规格中的响应时间与屏幕尺寸为首版验收默认目标；生成和自动修复的总耗时、尝试次数遵循现有运行配置，不承诺实时完成完整设计。
- 规格说明与用户交互以中文为主，RTL 代码、模块名、信号名、技术缩写和原始验证日志保留原文。
