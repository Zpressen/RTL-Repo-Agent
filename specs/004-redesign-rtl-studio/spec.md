# Feature Specification: RTL Studio 参考页面改版

**Feature Branch**: `main`（沿用当前分支；功能目录独立编号 `004-redesign-rtl-studio`）

**Created**: 2026-10-20

**Status**: Implemented — 本地实现及契约验收通过；真实模型、修复与公网发布未执行

**Input**: User description: “按照它的页面设计来拟定修改计划。”最新补充：“RI、RSI 入口不用保留，尽量按照 `/home/mokita/RPG-ZeroRepo/web/RTL Studio 演示-html` 的排版来。”

目标是按参考稿重排现有 RTL 工作台，使投资人同时看到执行过程、工程证据和交互能力。参考稿决定视觉与信息层级，仓库保存的真实材料决定案例内容和验证结论。新版不保留 RI、RSI 页面入口，不增加额外导航栏或宣传区；持续对话是相对参考稿必须补入的能力。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按参考稿的三栏布局演示设计过程 (Priority: P1)

作为演示者，我希望页面与参考稿具有相同的布局和视觉层级，通过左侧步骤和中间五个页签展示设计过程。

**Why this priority**: 本次主要需求是按已有设计稿改版，避免扩展成复杂平台。

**Independent Test**: 加载归档 E203，在五个内容页签和八个步骤间切换，对照参考稿检查画面；无需调用模型或启动仿真。

**Acceptance Scenarios**:

1. **Given** 桌面打开页面，**When** 案例加载完成，**Then** 顶部为品牌、案例、模式、状态、回放和下载入口，细进度条位于其下，主体为左侧纵向时间线、中间工程证据、右侧指标及 Agent 信息；没有 RI、RSI 主导航或大型宣传区。
2. **Given** 用户选择左侧步骤，**When** 切换到规格解析、架构规划、RTL 生成、语法检查、仿真验证、差异定位、自动修复或最终复验，**Then** 中间打开相应的规格、架构、RTL 代码、仿真与波形、定位与修复页签，选中状态清楚。
3. **Given** 某阶段有多轮候选，**When** 展开该阶段，**Then** 可查看有记录的候选轮次及结果；默认仍保持八个主步骤，缺失事件不补造。
4. **Given** 正在历史回放，**When** 暂停、继续、从头播放或手动选步骤，**Then** 只改变展示位置，不启动真实执行；进度表示回放位置，没有原始时间的阶段不生成耗时。
5. **Given** 案例未记录单独定位过程或某项检查，**When** 查看对应步骤，**Then** 显示未单独记录或材料缺失，而不是播放一段虚构的完成过程。

### User Story 2 - 查看真实代码、波形与修复证据 (Priority: P1)

作为投资人，我希望从规格和模块规划查看生成代码，再定位真实失败并比较修复后结果，确认 Agent 输出有可检查的证据。

**Why this priority**: 真实报告、版本和波形是建立技术信任的核心。

**Independent Test**: 用已保存的 E203 第 5 次失败候选与最终通过记录，检查架构、文件清单、报告、波形和前后差异。

**Acceptance Scenarios**:

1. **Given** 打开 E203，**When** 查看规格、架构及文件列表，**Then** 显示执行单元子系统、9 个规划模块及对应版本的 10 个 RTL/定义文件；不会显示参考稿完整 CPU 的 14 模块、16 文件结论。
2. **Given** 查看规格或架构，**When** 展开原文、约束、职责及已有划分依据，**Then** 能查看其来源；重新整理的摘要与历史产物有区别，未保存的分析不冒充当时的 Agent 发言。
3. **Given** 选择 E203 第 5 次候选，**When** 定位仿真差异，**Then** 显示报告中的 1/222 不匹配采样和 1125 ps 的 `wbck_o_wdat` 差异，并打开该验证绑定的 DUT / Reference 波形。
4. **Given** 已选择失败版本的信号与时间窗口，**When** 切换修复后的最终记录，**Then** 保留兼容的信号和时间范围，显示对应 RTL、0/222 不匹配及最终 PASS，不混用前后版本的报告或波形。
5. **Given** 查看定位与修复，**When** 打开失败摘要、代码差异、候选结果及最终复验，**Then** 展示已有证据，未保存的根因说明明确标为未记录，不套用参考稿的加载符号扩展修复故事。
6. **Given** 已选择验证记录，**When** 查看结果，**Then** 候选检查与最终系统复验分别标明范围；没有独立指令用例结果时不生成十项指令回归表，没有综合报告时不宣称综合通过。

### User Story 3 - 在右侧持续对话并观察执行动态 (Priority: P1)

作为演示者，我希望右侧保留参考稿的指标与动态，并能持续输入关于当前任务的问题、打开回答依据或发起现有操作。

**Why this priority**: 参考稿只有轨迹列表，持续可交互对话是已有产品的硬性要求。

**Independent Test**: 使用可控回复和操作状态，连续交互、切换五个页签并模拟断线恢复，检查草稿、上下文和输入区；不依赖真实模型验收。

**Acceptance Scenarios**:

1. **Given** 用户正在编辑内容，**When** 切换阶段或页签，**Then** 草稿和消息保留，输入区可继续操作，不被不断增长的执行动态挤出桌面视口。
2. **Given** 选中某模块、版本或验证，**When** 提问“为什么这样划分”或“解释当前差异”，**Then** 问题关联发送时的选择，回复引用可打开的已有证据；之后切换案例不会改变该问题的原始归属。
3. **Given** 用户明确要求生成并验证、重新验证或修复，**When** 目标明确且该能力可用，**Then** 复用现有操作流程并显示真实状态；普通浏览与解释不启动这些操作，同一请求不重复执行。
4. **Given** 问答或某项执行能力不可用，**When** 用户编辑或尝试相关请求，**Then** 仍可输入并保留草稿，相应发送或操作入口给出简短原因；模型问答和重型执行分别反映可用性。
5. **Given** 有新执行事件，**When** 更新右侧动态，**Then** 显示有来源的工具事件或摘要，不把参考稿预设文字当作实际推理，也不声明尚未提供的执行暂停、审批或接管功能。
6. **Given** 两个独立访客打开同一案例，**When** 一个访客发送消息或发起操作，**Then** 另一个访客看不到其私有对话、草稿和运行材料。

### User Story 4 - 用同一布局切换四个真实案例 (Priority: P2)

作为演示者，我希望通过顶部一个案例选择器展示 E203、AES 加密、AES 解密与 SDC，而不需要额外的项目管理页面。

**Why this priority**: 延续现有多案例能力，展示适用范围，同时保持参考稿的简洁排版。

**Independent Test**: 依次切换四个案例，核对各自规划、文件、报告及波形，并检查缺失提示和旧链接行为。

**Acceptance Scenarios**:

1. **Given** 选择 AES 加密、AES 解密或 SDC，**When** 加载内容，**Then** 分别显示 3、5、5 个规划模块，以及各自规格、RTL、最终 PASS 报告和真实波形。
2. **Given** 案例没有修复前波形或完整采样统计，**When** 查看对比或摘要，**Then** 显示缺失说明，仍可查看已有最终结果，不借用 E203 数据、不填零或虚构修复次数。
3. **Given** 切换案例或使用浏览器刷新、前进/后退，**When** 恢复内容，**Then** 时间线、指标、当前证据和对话上下文属于相应案例；对话中的旧证据链接仍指向原案例。
4. **Given** 用户从旧的 RI 或 RSI 页面地址进入，**When** 新版打开，**Then** 进入设计工作台并尽可能保留有效案例选择，页面中没有 RI、RSI 入口或独立故事展示区。

---

### User Story 5 - 下载当前结果的公开证据包 (Priority: P2)

作为投资人或演示者，我希望下载当前验证的公开材料，在离开网页后仍能检查结果与受测代码的对应关系。

**Why this priority**: 将参考稿的下载按钮变成可核查的交付物。

**Independent Test**: 下载 E203 单次验证和修复前后对比两类证据包，核对材料清单、对应版本与公开范围。

**Acceptance Scenarios**:

1. **Given** 选中了可公开展示的验证，**When** 下载证据包，**Then** 获得相关规格、规划、受测 RTL、报告、已有波形和可读清单，清单列明案例、版本、验证标识和文件完整性信息。
2. **Given** 正在查看前后对比，**When** 下载对比证据，**Then** 两个版本及各自报告、波形归属清楚，缺失材料列在清单中，不自动用其他记录补齐。
3. **Given** 有私有材料或无法导出的记录，**When** 请求下载，**Then** 不输出凭据、私有对话、访客标识、内部提示及服务器绝对路径；不能下载时显示具体原因。

### Edge Cases

- 历史回放时查看最终记录，只能表明该归档记录已通过，不暗示刚完成现场仿真；手动选阶段也不自动完成其他步骤。
- 顶部所选验证的最终状态与左侧回放位置分别标识，避免“历史最终 PASS”被误读为当前步骤已经执行完成。
- 有候选日志摘要但无该轮代码或波形时，允许查看摘要，缺失入口说明原因。
- 语法检查与综合检查、内部诊断计数与采样不匹配数、模块数与文件数不可互相替代。
- 版本、验证与波形绑定缺失或不一致时，提示异常，不展示无依据的配对结论。
- 两个波形的信号或时间范围不同，只比较兼容部分；未知值遵循该次验证的已有比较规则，不当作自动一致。
- 长文件名、代码、动态和长波形在自身区域滚动，不挤压输入区；窄屏重排后仍能访问核心功能。
- 连接中断、请求过晚返回或发送后切换案例时，保留草稿与证据，回复仍属于发送时案例，不重复执行请求。
- 模型可用但仿真不可用，或反过来时，分别显示对应能力状态，不由一个连接标识推导全部就绪。
- 无法导出、下载失败或部分材料缺失时，解释具体情况，不将公开证据包描述为完整私有运行复现环境。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 页面 MUST 以 `web/RTL Studio 演示-html/Demo.dc.html` 为视觉依据，沿用深色背景、薄边框、圆角卡片、绿色主强调、紧凑顶部栏、细进度条和三栏信息结构。桌面中间证据区占最大宽度；除真实案例文字、案例选择器、持续对话及窄屏适配外，布局和信息层级尽量贴近参考稿，不另加宣传区。
- **FR-002**: 顶部 MUST 显示品牌、案例选择、历史/实时模式、所选任务状态、回放及证据下载；不保留 RI、RSI 入口、独立故事展示区或额外主导航栏。旧 RI / RSI 地址进入工作台，不要求重建故事页面。
- **FR-003**: 左侧 MUST 按参考稿组织八个主步骤：规格解析、架构规划、RTL 生成、语法检查、仿真验证、差异定位、自动修复、最终复验。阶段分组不构成执行证据，未单独记录的步骤明确说明；多轮候选默认收起，在相关阶段内展开。
- **FR-004**: 中间 MUST 提供“规格、架构、RTL 代码、仿真与波形、定位与修复”五个页签，点击步骤和候选记录联动相应内容及已有证据，保留兼容的模块、信号和时间窗口。
- **FR-005**: 历史回放 MUST 支持播放、暂停、继续、从头播放及手动选步骤，不创建执行任务或付费问答。进度仅表示记录播放位置；无原始时间不补造耗时，实时执行没有可量化进度时显示阶段状态。
- **FR-006**: 规格页 MUST 提供原文、简短摘要与有来源的约束，重新整理的摘要与原始分析可区分；缺失约束标为未记录或待确认。
- **FR-007**: 架构页 MUST 展示当前规划的模块、职责和层次，可打开模块 RTL 及已有划分依据，不虚构设计决策。
- **FR-008**: RTL 页 MUST 提供所选版本的文件列表、只读代码、版本标识及已有版本差异；模块与文件分开计数，定义文件不计为设计模块。
- **FR-009**: 仿真页 MUST 展示所选验证的真实结论、检查范围、报告及已有统计，候选检查和最终复验分别标识；无指令用例或综合记录时不得生成对应表格或通过声明。
- **FR-010**: 波形 MUST 来自当前验证绑定的真实材料，支持关键 DUT / Reference 信号、缩放、平移、游标读数及已有差异定位；波形视觉相似不替代报告结论。
- **FR-011**: 前后比较 MUST 分别绑定 RTL 版本、报告和波形，保持兼容信号与窗口；缺失一侧时说明原因并提供已有记录，不生成替代波形。
- **FR-012**: 定位与修复页 MUST 组合已有失败摘要、差异位置、代码变更、候选验证及最终复验；无根因记录时明确说明，新增解释不冒充历史记录。
- **FR-013**: 右侧 MUST 沿用参考稿的紧凑指标与 Agent 信息层级，并加入持续对话。指标按实际数据命名，例如规划模块、候选验证次数、最终系统验证；没有材料定义修复次数时不显示虚构次数，缺失值显示未记录。
- **FR-014**: 对话 MUST 支持文本输入、多轮消息、发送状态和证据引用；切换步骤或页签保留草稿和消息。桌面三栏布局中输入区保持可见，动态和消息限制在各自可浏览区域，动态可折叠以给对话留出空间。
- **FR-015**: 每条问题 MUST 关联发送时案例及已有模块、版本、验证等选择；之后切换选择不能改变问题归属，回答引用打开原所属材料。
- **FR-016**: 执行动态 MUST 来源于真实事件、工具结果或明确标注的摘要，不将参考稿文字作为实际推理，不声明尚未支持的暂停执行、审批或接管；暂停回放与暂停真实执行不得混淆。
- **FR-017**: 用户明确要求且目标清楚、能力可用时，系统 MUST 复用现有生成并验证、重新验证及修复操作，显示真实状态并避免重复启动；普通浏览与解释不触发执行。
- **FR-018**: 问答和各执行能力 MUST 分别反映可用性；不可用时仍可编辑并保留草稿，对无法完成的发送或操作给出简短原因，不以历史 PASS 推导执行就绪。
- **FR-019**: 案例切换与结果更新 MUST 保持材料归属，独立访客之间隔离私有对话、草稿和运行材料，重排布局不得扩大材料公开范围。
- **FR-020**: 所有案例数字、代码、层次、波形和结论 MUST 使用真实材料替换示意稿内容。E203 范围为执行单元子系统；14 模块、16 文件、十项指令回归和符号扩展补丁不作为本案例事实。
- **FR-021**: 四个案例 MUST 共用同一布局，通过顶部选择器切换；缺少修复前记录或采样统计时说明缺失，不借用其他案例或填零。
- **FR-022**: 证据包 MUST 围绕选中验证或前后对比提供可公开的规格、规划、受测 RTL、报告、已有波形与清单；清单含案例、版本、验证标识、文件完整性及缺失说明，不混入其他运行材料。
- **FR-023**: 导出 MUST 排除凭据、私有对话、访客标识、内部提示与服务器绝对路径；不可导出或失败时明确反馈，不保留无效下载按钮。
- **FR-024**: 页面 MUST 在 1440×900 与 1280×800 桌面视口下保持三栏、页签和输入区可用；390×844 窄屏可重排或折叠，案例、五页签、证据及对话可操作，长代码或波形不造成页面整体横向溢出。
- **FR-025**: 有效的原案例与验证链接 MUST 可继续访问；支持刷新及浏览器前进/后退恢复公开证据选择，公共链接不暴露私有会话或聊天内容。旧 RI / RSI 地址按 FR-002 进入工作台。

### Key Entities *(include if feature involves data)*

- **案例**：设计对象、公开范围及其规格、规划、版本、验证与可比较组合。
- **主步骤与执行事件**：八个展示分组及其实际事件，含顺序、状态、来源、已有时间、候选轮次与证据；回放位置独立于执行状态。
- **规格与规划**：原文、展示摘要、约束、模块职责和层次，保留来源和未确认项。
- **RTL 版本**：受测文件集合、完整性信息、模块关系和可比较的前后版本。
- **验证与波形**：所属版本、检查范围、结论、报告、统计、差异位置及真实信号记录。
- **对话上下文**：访客自己的草稿、消息、发送时选择和操作状态，与公开材料分开。
- **证据包**：所选验证或比较的可公开材料及清单，说明归属、完整性和缺失。

## Success Criteria *(mandatory)*

### Measurable Outcomes
