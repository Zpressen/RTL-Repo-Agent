# Feature Specification: RTL Agent 单机安全部署

**Feature Branch**: `main`（本次创建部署规格，不新建分支）

**Created**: 2026-10-16

**Status**: Ready for planning

**Input**: 用户要求先理解 Deep Valley Chip 服务器 handoff，再分析如何将现有 RTL Agent 安全部署到该服务器。结合前序澄清，以直接部署在 `39.107.243.176` 为默认，不以另一台大内存服务器或其私网地址为前置条件；保留现有单页演示和真实交互能力。

2026-10-16 补充要求：明确仓库中需要上传和应排除的文件，避免携带无关开发文档、历史工作区和本机环境；单独梳理服务器环境、运行配置与私有凭据。现状分析见 [deployment-inventory.md](deployment-inventory.md)，具体打包和安装实现留给计划阶段。

## 部署背景与已确认约束

- **业务目标**：投资人在现有 design 域名观看简洁工作台，演示者可以持续提问、发起真实任务，并追溯 RTL、验证报告与波形。静态网页可访问或本机验收成功都不能单独代表线上交付完成。
- **现有入口**：公网地址 `39.107.243.176`，SSH 为 `dev@39.107.243.176:22`；主站、www、design 三个 HTTPS 域名已在 handoff 中列明。沿用现有 Caddy 入口，不替换主站托管方式。
- **发布权限**：`/home/dev/deepvalleychip-site/` 为 dev 可写准备目录；主站和 design 的实际服务目录分别为 `/srv/deepvalleychip/main/`、`/srv/deepvalleychip/design/`；`/etc/caddy/Caddyfile` 的正式变更需要 root。静态资源更新与路由配置变更是不同的发布步骤。
- **本会话已核实的现状**：该公网机约 2 核、1870 MiB 内存，约 32 GB 可用磁盘；design 配置目前仅提供静态文件，没有连接 RTL 交互后台。28989 端口是现有 CAD Responses API，不是本项目后台。以上是 2026-10-16 的检查记录，正式发布仍需重新预检。
- **handoff 的两机建议**：其中“大内存服务器私网 IP/端口”描述了一种未来拓扑，不意味着单机部署不可行；实际配置中的示例地址不能当作已存在的后台。后续默认采用同机部署并限制后台直接访问；是否需要扩容依据实测决定。
- **既有成果**：已有四例历史展示包，本机真实两轮模型问答与对话发起的 E203 验证已经通过；完整前端包已暂存在服务器 dev 准备目录，尚未成为线上正式服务。原功能范围及证据规则见 [001-rtl-agent-demo/spec.md](../001-rtl-agent-demo/spec.md)。
- **本规格与旧计划的关系**：本规格替代旧演示计划中“必须另有计算服务器”的部署前提，不取消现有工作台的生成、验证、修复和证据真实性要求。后续部署计划需同步旧部署文档中不再适用的两机假设。
- **本轮边界**：产出部署需求与验收口径；不安装依赖、不修改线上路由、不切换站点、不把质量检查通过写成实际部署完成。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从正式域名使用真实 Agent (Priority: P1)

作为演示者，我希望只打开受保护的 design 域名，就能浏览案例、连续提问并发起真实验证，无需依赖自己电脑上临时运行的后台。

**Why this priority**: 投资人需要看到真实可交互的服务，只有历史展示无法满足演示目标。

**Independent Test**: 从另一台设备访问正式域名，进入演示，完成多轮上下文问答，再从对话发起 E203 验证并打开该次运行的报告和波形。

**Acceptance Scenarios**:

1. **Given** 演示者具备有效访问资格，**When** 打开正式 design 域名，**Then** 一个页面中显示常驻对话和“架构 / 代码 / 验证”三个标签，四个预置案例均可加载。
2. **Given** 已选择一个案例，**When** 演示者自由提问并继续追问，**Then** 真实模型结合当前案例与已有对话回答，涉及设计事实时提供可打开的证据入口；切换标签和刷新后保留已保存内容。
3. **Given** 已选择 E203 的受测 RTL，**When** 从对话发起重新验证，**Then** 服务器真实执行现有验证流程，展示接收、执行和终态，并绑定本次 RTL、报告及真实 DUT/Reference 波形。
4. **Given** 演示者的开发电脑没有运行任何服务，**When** 通过正式域名提问和发起验证，**Then** 操作仍能由服务器完成。
5. **Given** 后台暂不可用，**When** 用户继续操作，**Then** 页面明确显示不可用能力与重连入口，保留草稿和可浏览历史；不提供冒充实时回答或执行结果的替代内容。

### User Story 2 - 在同一服务器保护已有业务并控制资源 (Priority: P1)

作为服务器维护者，我希望 RTL Agent 与现有站点及 CAD 服务共存，并了解这台服务器能够实际承载哪些任务。

**Why this priority**: 当前机器资源有限，部署不能影响既有网站或凭经验承诺完整 Agent 已可运行。

**Independent Test**: 记录现有服务基线，在一次真实执行和同时问答期间持续访问主站、www 与已有 CAD 服务，检查任务并发、资源边界及服务连续性。

**Acceptance Scenarios**:

1. **Given** 现有三个域名和 CAD 服务在运行，**When** 准备、启动或回滚 RTL 服务，**Then** 主站和 www 的内容及路由保持原状，CAD 服务的目录、配置及监听不被覆盖。
2. **Given** 同机后台已部署，**When** 从公网直接访问后台进程，**Then** 无法绕过受保护站点入口；授权用户仍能正常使用网页、对话和运行状态更新。
3. **Given** 已有一个 RTL 执行任务，**When** 同一或其他会话再次提交任务，**Then** 不启动第二个执行任务，用户得到忙碌提示，已有问答与历史浏览仍可使用。
4. **Given** 任务资源不足或运行超过预算，**When** 服务拒绝或终止该任务，**Then** 用户看到实际原因，已保存结果保留，现有站点和 CAD 服务不被终止。
5. **Given** 某项生成、验证或修复依赖尚未准备好，**When** 维护者检查能力或用户尝试操作，**Then** 明确列出未就绪项，不将历史结果、任务合并成功或进程退出成功当作该能力已验收。

### User Story 3 - 控制访问、凭据和执行范围 (Priority: P1)

作为演示负责人，我希望外部访问者只能在授权范围内使用演示，模型凭据、参考设计与运行目录受到保护。

**Why this priority**: 服务可发起模型调用及工具执行，公开部署必须具备与能力相匹配的访问和数据边界。

**Independent Test**: 分别以未授权访问、其他会话、异常路径和超范围指令尝试访问或执行，核对拒绝结果及规格、参考设计和测试平台的完整性。

**Acceptance Scenarios**:

1. **Given** 请求没有有效演示访问资格，**When** 请求受保护页面、对话、运行数据或执行操作，**Then** 不返回受保护内容，也不产生模型调用或任务。
2. **Given** 已授权的一个会话，**When** 引用另一个会话的私有运行、伪造案例目标或提交任意命令与本地路径，**Then** 请求被拒绝，其他会话数据不泄露。
3. **Given** 正在生成或修复，**When** Agent 读写设计文件，**Then** 只在本次任务获准的工作范围内修改生成 RTL，原始规格、参考设计及测试平台保持不变。
4. **Given** 维护者准备或更换凭据，**When** 用户查看网页文件、下载产物、读取普通日志或错误提示，**Then** 无法取得模型密钥、站点访问秘密、私有配置或未授权目录内容。
5. **Given** 使用既有外部模型服务，**When** 发送设计资料，**Then** 仅发送当前任务已获授权的资料范围；换服务端点或扩大资料范围不能通过页面输入暗中完成。

### User Story 4 - 可控发布、持续运行与恢复 (Priority: P1)

作为维护者，我希望准备、正式切换和回退都有清晰边界，并且退出 SSH、重启服务或重启服务器后演示仍可恢复。

**Why this priority**: 现场演示需要稳定运行，更新不能破坏现有站点或丢失已完成结果。

**Independent Test**: 完成一次候选发布和受控故障回退，再分别测试管理连接断开、服务重启和服务器重启，检查访问、会话和执行记录。

**Acceptance Scenarios**:

1. **Given** dev 已准备候选版本，**When** 尚未执行正式切换，**Then** 可以核对完整版本和文件摘要，现有正式站点继续服务旧版本；仅暂存不标记为上线。
2. **Given** 即将正式发布，**When** 有权限的维护者应用已评审变更，**Then** 保留原站点和配置备份，只改变 design 的必要内容；候选入口配置校验失败时不替换有效配置。
3. **Given** 维护者退出 SSH，或服务意外退出后恢复，**When** 演示者再次访问，**Then** 不依赖原管理终端存活，已保存会话与结果可读取，状态不明的任务明确标记而不自动重跑。
4. **Given** 服务器重启且基础服务已就绪，**When** 用户重新进入演示，**Then** 受保护入口、后台与执行服务自行恢复，原有站点仍可用。
5. **Given** 新版本无法满足访问或交互验收，**When** 维护者执行回退，**Then** 恢复此前可用版本及其入口配置，保留新版本的诊断和已有会话、运行证据，不将失败版本继续当作正式发布。
6. **Given** 已形成候选发布清单，**When** 在未携带开发电脑工作区和环境的目标目录准备运行，**Then** 必要源码、四例材料、验证依赖及运行输入均可解析，服务从服务器自己的持久数据恢复；无关文档、开发会话和缓存不进入运行包。

### Edge Cases

- 页面能够加载，但交互请求被静态页面响应替代、转发错误或携带恢复会话的额外字段：必须识别交互失败，不能仅凭页面成功打开判为上线。
- 前端与后台版本不一致、完整资源未上传或发布期间有旧页面保持打开：提供可诊断错误，维持旧版本所需资源，不能混用不同验证的报告和波形。
- 模型凭据缺失、过期，或上游超时、断流、回复格式错误：有限处理后明确失败，保留草稿及对话，不能无限调用、重复计费或伪造回答。
- 用户重复点击、刷新、断线重连或后台重启：恢复已有记录，不重复启动模型请求或执行任务；无法确认执行状态时不报告成功。
- 磁盘不足、内存紧张、任务超时或执行进程退出：结束或拒绝受影响任务，保留有效历史和结果，不清空整个工作区或误停既有业务。
- 历史包缺少失败波形、采样统计或完整受测依赖：说明缺失及可验证范围，不补造统计、不借用其他版本的波形。
- dev 没有 root 权限，或候选配置校验不通过：保留准备结果，明确等待哪一步；不得自动提升运行账户权限、扩大目录权限或覆盖整份站点配置。
- 单机无法通过所需能力的资源验收：报告实际峰值与失败点，保留未完成事项；同机扩容可作为后续选择，不暗中换模型、取消既有依赖或重新强制要求第二台机器。
- 按扩展名排除文档误删案例规格，漏传运行资源，或复制本机环境导致版本和路径不兼容：发布检查必须识别，不能等到现场操作时才发现缺失。
- 复制本机数据库、会话签名秘密、未完成任务或预检缓存：不能成为生产初始化方式；升级时也不得用初始化包覆盖已有生产会话和运行数据。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须以现有公网服务器为默认部署目标；默认方案不要求另一台计算服务器的私网地址，正式入口继续使用既有 design 域名及加密访问。
- **FR-002**: 部署必须沿用现有单页工作台和四个预置案例，不增加项目管理、账号注册、在线编辑或通用远程终端界面。
- **FR-003**: 正式域名必须支持真实多轮问答、证据跳转和会话恢复；服务能力不能依赖演示者的开发电脑或登录终端持续在线。
- **FR-004**: 系统必须部署现有生成并验证、重新验证、分析并修复三种受控入口，分别报告就绪状态；完整部署交付前，每种承诺能力均须在目标服务器真实执行验收。能力不齐时明确标记未完成，不擅自缩减原功能范围。
- **FR-005**: 所有执行结论必须来自服务器实际运行并绑定对应 RTL 版本、验证报告及波形；历史记录和实时结果始终可区分，缺失资料保留为未知或未记录。
- **FR-006**: 所有受保护内容、对话及执行必须经过访问校验，未授权请求不得触发付费调用、创建任务或读取私有运行；会话与案例目标必须匹配。
- **FR-007**: 后台、工具执行和私有运行产物不得提供绕过受保护入口的公网访问方式；已有无关服务的访问方式不在本功能中自行调整。
- **FR-008**: 用户输入只能触发预置案例范围内的既有操作；不能据此执行任意命令、指定任意路径、改变模型端点或访问其他会话的私有内容。
- **FR-009**: 运行账户必须采用完成任务所需的最小权限；特权仅用于必要安装和正式发布，不作为网页或 Agent 的日常运行权限。写入限于允许的运行、缓存和诊断范围。
- **FR-010**: 每次实时运行必须隔离生成 RTL 和中间产物；规格、参考设计、测试平台及历史受测快照保持只读，不能为使验证通过而更改比较规则。
- **FR-011**: 模型及站点凭据必须由受限运行配置提供，不能进入公开网页、下载产物、发布摘要或普通日志；不得从其他服务或其他进程取得凭据来替代现有配置。
- **FR-012**: 外部模型端点和可发送的设计资料范围必须明确登记并遵循已有授权；使用当前任务证据，不能上传整个私有工作区或无关会话。模型和必需依赖不被静默替换或禁用。
- **FR-013**: 全局同时最多执行一个 RTL 任务；并发问答与历史浏览保持可用。重复提交、恢复连接和服务启动不得自动重跑既有任务。
- **FR-014**: 发布前必须检查目标机资源及所需依赖，包括模型服务、生成修复后端、验证工具和参考材料；将可用、缺失及未经实际运行验收的能力分别说明。
- **FR-015**: 任务必须有明确的运行预算和资源边界；资源不足、超限及异常退出均应产生可诊断终态，只回收本任务拥有的执行进程，保护其他服务。
- **FR-016**: 主站、www、现有 CAD 服务及其目录和配置必须维持既有行为；部署不得复用其端口或覆盖其文件。只应用 design 所需的变更。
- **FR-017**: 每个候选发布必须可标识并核验完整内容，包含所有网页资源和四例展示材料；不得仅复制入口页面。禁止公开上传完整私有 Agent 工作区作为静态资源。
- **FR-018**: 必须区分 dev 准备、依赖与后台预检、特权发布和正式域名验收；切换前备份已用版本与入口配置，校验失败时保留原服务。
- **FR-019**: 服务必须在管理连接断开后持续运行，并在异常退出或服务器重启后恢复；会话、运行、版本及验证证据持久保存，未完成任务状态明确且不自动重跑。
- **FR-020**: 发布必须支持有界时间内回退旧版本及入口配置，保留运行证据和诊断；准备、暂存、启动、部分能力可用及完整验收通过不能混为同一状态。
- **FR-021**: 维护者必须能够定位连接失败、能力缺失和单次任务错误；诊断包含发布及运行标识，用户侧提示不泄露凭据或私有系统细节。
- **FR-022**: 上线判定必须经正式 design 域名完成真实交互及安全边界测试，并与主站、www 和 CAD 服务基线比较；本机成功、替身测试、静态包校验或后台健康状态不能单独替代这一判定。
- **FR-023**: 必须提供明确的文件发布清单，区分公开网页、私有运行代码、四例运行与验证材料、维护材料以及排除项；每项记录来源、用途、目标可见范围、大小和摘要，不能直接打包整个仓库。
- **FR-024**: 开发说明、测试报告、编辑器状态、版本历史、本机环境和无关历史运行默认不上传；任务规格、运行时读取的资源及许可文件按实际用途保留，不能只根据文件扩展名裁剪。
- **FR-025**: 生产初始化只能导入经审查的四例证据及必要版本关联，使用服务器自己的会话和运行状态；不得迁移无关本地消息、任务、签名秘密和检查缓存。后续升级保留生产已有数据，不得重新初始化覆盖。
- **FR-026**: 必须在目标环境重建并验证运行依赖及必要的本地构建产物，明确网页、问答、验证、生成修复各自的依赖；不能复制开发电脑环境或仅安装全部通用依赖来代替兼容性验证。
- **FR-027**: 生效配置中的解释器、文件路径、模型、生成修复后端及知识服务地址必须按服务器环境逐项核对；配置模板与实际秘密分开交付。验证材料若包含开发机路径，须完成可审计的路径适配并重新验证，不更改测试刺激和比较规则。

### Key Entities *(include if feature involves data)*

- **部署目标与既有服务基线**：服务器身份、资源、允许变更的站点、现有服务归属和发布权限；用于核对部署前后的影响。
- **发布版本**：候选内容、来源版本、文件摘要、准备及正式状态、上一个可用版本和回退记录；与服务采用的版本关联。
- **文件与环境清单**：每类发布文件的来源、用途、可见范围及校验信息，目标环境的依赖版本与兼容性结论；实际秘密不属于清单内容。
- **能力就绪记录**：问答、生成、验证、修复各自的依赖、资源检查、真实执行证据和未通过原因；不能只记录统一“在线”。
- **演示访问与会话**：访问资格、所属案例、保存的消息、当前选择和操作归属；公开历史与会话私有运行具有不同可见范围。
- **运行与证据关联**：执行请求、资源预算、状态、RTL 版本、验证报告、波形及失败诊断；延续已有证据规则。
- **受限配置与授权范围**：现有模型端点、凭据引用、可发送的设计资料和允许操作范围；其秘密内容不属于发布产物。
- **部署验收记录**：正式域名上的真实交互、既有业务连续性、访问拒绝、重启恢复及回退结果；每项有可核验的结论与限制。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 通过正式 design 域名进入工作台，四个预置案例均可切换并查看各自真实 RTL、报告和已有波形；关闭开发电脑上的服务后仍能完成此流程。
- **SC-002**: 正式域名上的同一会话连续完成 10 轮真实设计问答，其中至少 2 轮是基于前文的追问；涉及具体设计结论的回复具有有效证据入口，刷新后10轮记录完整保留。已接收消息在3秒内有可见反馈；可用模型的回答在既定120秒预算内返回或明确报告失败。
- **SC-003**: 在目标服务器通过对话完成至少一次 E203 独立系统复验、一次预置规格生成并验证及一次已有失败版本的修复尝试；各操作有真实终态和版本证据。独立复验须得到受测版本的真实通过结论；生成或修复的技术结果如实记录，实际尝试不保证所有设计均成功收敛，但依赖缺失、启动失败或环境故障不能算作相应能力已验收。
- **SC-004**: 未授权访问、直接访问后台、跨会话私有引用、跨案例执行和任意路径/命令五类测试全部被拒绝；每类测试均确认没有额外模型调用或执行任务。
- **SC-005**: 在一次真实 RTL 执行期间完成至少3轮问答，并对主站和www分别发起30次访问、对既有CAD服务发起10次既有健康检查，全部保持预期响应，站点与服务配置无非预期变化；工作台普通浏览操作95%在5秒内得到反馈。记录目标机资源峰值，不能发生资源耗尽导致既有服务退出。
- **SC-006**: 对同一执行请求进行重复点击、刷新和断线恢复后，服务端只存在一个实际执行实例；结果产生后5秒内可见，恢复会话不会创建第二个任务。
- **SC-007**: 退出管理连接后持续30分钟仍可访问和交互；一次服务重启后60秒内恢复，一次主机重启后基础依赖可用起120秒内恢复。已完成会话与证据全部保留，未完成操作不被自动重跑或虚假标记为通过。
- **SC-008**: 在一次受控发布失败演练中，维护者5分钟内恢复上一可用版本及入口配置，保留已有会话与运行证据，主站和www内容不变。
- **SC-009**: 检查全部公开发布文件、下载入口和普通日志，不存在实际凭据、参考设计源文件或私有会话目录泄露；生成修复验收前后原始规格、参考设计和测试平台摘要保持一致。
- **SC-010**: 维护者可在2分钟内从发布和能力记录区分已暂存、后台已启动、部分能力可用及正式域名完整验收通过，并定位每个未就绪能力的实际阻塞原因。
- **SC-011**: 在仅具备已声明系统前置条件、未携带开发电脑目录的目标环境中，用发布清单完成一次准备演练；四例规格与证据全部可读，三类既有执行入口的运行依赖均可加载，排除项及本地私有会话迁移数量为0。
- **SC-012**: 生效配置的路径和服务连接逐项检查通过，全部指向部署批准的目标资源；四例真实验证使用目标机材料与工具链。一次版本升级后，升级前已保存的生产会话及验证结果全部保留，初始化包不覆盖这些记录。

## Assumptions

- 第一版供一名演示者及少量受邀观看者使用，沿用简单的演示访问保护，不引入注册、多租户或开放匿名执行。
- 本规格以当前公网机单机部署为默认。约2GB内存是需验证的资源约束，不等于已经证明它能承载完整运行；若不满足验收，形成明确阻塞和同机扩容建议，另行决定资源变更。
- 模型推理由现有外部模型服务完成，不要求在该服务器本地运行大模型或配置本地加速硬件。
- 现有四个案例、Agent三种执行入口和证据关联规则继续适用；本功能负责部署及线上可信使用，不重新设计工作台或替换 Agent 算法。
- 模型、生成修复后端及必需知识服务继续采用当前有效配置，是否能够在服务器使用须预检与实测；不能为了省资源静默取消必需依赖。
- dev负责可逆准备；必要特权安装、正式站点和入口变更由具备root权限的维护者执行。现有dev不能免密sudo是交付条件，不代表可省略特权步骤或要求另一台机器。
- 本次为规格阶段，不执行服务器部署或扩大既有凭据使用范围。具体安装方法、进程管理、入口路由、端口、目录布局及root操作步骤留给部署计划。
- 文件及环境清单是计划输入，不代表已经实现可移植初始化导出、精简依赖锁定或验证脚本路径适配；这些缺口必须在后续计划和任务中明确安排。
- 上述交互响应目标以可用的网络和外部模型服务为前提；完整生成与修复的运行时长遵循既有任务预算，不承诺在三分钟内生成完整设计。
