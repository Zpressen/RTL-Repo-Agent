# 运行上下文审计与优化

2026-11-07。本轮确认的主要浪费是跨阶段重复原文与派生事实、小模块携带系统全量证据，以及局部修复反复发送无关义务正文。优化只改变发送给模型的阅读视图；完整规格、来源、责任表、候选、合同及其内容指纹仍由本地权威产物保存和校验。

## 确认的问题与处理

| 位置 | 不必要的上下文 | 当前处理 |
| --- | --- | --- |
| Stage1 多文件事实抽取 | 后续批次回送此前完整事实表和派生合同；长文件分段已有优化，短文件批次仍遗漏 | 所有事实批次统一使用当前原文、已知模块名和规格索引；程序合并完整历史结果 |
| Stage2 首次责任抽取 | 全部原文证据之外，又发送 Stage1 派生事实正文 | 保留完整原文目录、事实 ID、事实内容指纹及结构约束；首次请求和修复共用精简视图 |
| Stage2 责任输出说明 | 示例对象遗漏状态访问与 EV 字段，与后附真实 schema 重复且不一致 | 线上请求保留规则与真实 schema，去掉过时示例 |
| Stage2 三候选 | 每份证据重复携带绝对路径、段落路径和内容哈希 | 按已有 EV ID 索引全部被引用原文；文件和段落元数据集中保存。三种候选、双轮排序和裁定保持 |
| Stage3 初次模块设计 | 小模块也携带整份系统证据目录 | 展开当前 RU、状态、约束、接口及边界引用的全部来源，并补充同一来源节的上下文；跨文件按文件及节联合定位 |
| Stage3 修复 | 普通块映射错误也重新展开系统全量证据 | 普通修复沿用模块证据；未知或未绑定来源等错误才扩展完整目录，继续支持上游来源绑定补充 |
| Stage3 修复候选 | 改一项义务时回送所有未改义务的长效果正文 | 展开目标义务；其余保留状态访问、责任、约束及实现块索引。模块框架和结构块继续可见；小候选只有变短才投影 |
| Stage3 错误反馈 | 每条未知来源错误各自附带整份允许 EV ID 列表 | 统一引用当前证据目录，避免逐条复制 |
| Stage4 | 已经是确定性任务组装 | 无模型请求，本轮不减少责任、义务、任务及规格覆盖要求 |
| Stage5 | 缩进 JSON、运行路径与字符计数；任务义务和状态对象内重复的同一原文 | JSON 紧凑序列化；运行元数据留在诊断；有实际收益时使用已有 EV 协议共享完整原文，任务契约保持完整 |

Stage6 与 debug 的完整 RTL、片段及失败证据本轮没有新增有损压缩。当前三例的实测记录来自规划请求，不足以将合并和 debug 的潜在重复换算成节省。Stage5 累积片段可能产生较大上下文，但删减它们需要进一步验证符号、函数与驱动关系；本轮仅对确认无信息损失的部分实施优化。

## 重现审计

```bash
.zerorepo/bin/python scripts/audit_planning_context.py \
  rtl_outputs/e203_ifu_system \
  rtl_outputs/_acceptance/api_validation_20261107/aes_inv_cipher_system_hard \
  rtl_outputs/_acceptance/api_validation_20261107/e203_exu_alu_system \
  --output rtl_outputs/_acceptance/context_efficiency_20261107/replay_audit.json
```

脚本不调用 API，不写入被审计案例；仅在临时目录创建注册表等辅助文件，并写入指定的审计报告。回放不替代真实模型质量或最终 RTL 功能验收。
